# v0.4 Plan: Decisions (2026-10-19)

Status: **accepted**. The v0.4 plan (strapdown, error budget, references, temperature stress,
observability) with review 3's corrections and the owner's decisions V1 to V6. Review 3's
formulas were re-checked numerically before recording (results below).

## 0. Axis-mapping correction (found while planning)

Phone portrait, screen to the driver: vehicle forward +x_b ≈ −z_p, left +y_b ≈ −x_p, up
+z_b ≈ +y_p; pitch (about +y_b) ≈ −x_p, yaw (+z_b) ≈ +y_p, roll (+x_b) ≈ −z_p. With the true
mount (roll 1°, pitch 12°, yaw 3°): e_xb^p = (0.056, −0.207, −0.977), e_yb^p = (−0.998,
−0.028, −0.051).

DESIGN 4 had used phone x/y values. On the nominal axes:

| | old | nominal axes |
|---|---|---|
| constant BI-sized accel bias, b·t²/2 (180 s) | ~10 m (x) | 26.2 m (z, B = 1.62e-3) |
| constant BI-sized pitch-gyro bias, g·b·t³/6 | ~1.4 km (y) | 843 m (x, B = 8.84e-5) |

These are **"position error if a constant bias of BI size were present"**, not the RMS or P95
of the GM-realised error, and not the true-mount value. True-mount values come from
projecting the sensor covariance: σ²_b,∥ = e_xbᵀ Σ_b^p e_xb (same for the pitch gyro), and
the realised distributions from the v0.4 experiments.

## 1. Strapdown (step 2)

```
C_np,k+1 = C_np,k Exp([ω̄_k]× Δt_k),   ω̄_k = (ω̃_k + ω̃_k+1)/2
a_n,k    = C_np,k f̃_k + g_n            (C_np,k+1 computed first, then a_n,k+1)
v_k+1    = v_k + (a_n,k + a_n,k+1)/2 Δt_k
p_k+1    = p_k + (v_k + v_k+1)/2 Δt_k
```
Rotation matrices (no Euler). Measurement timing per the contracts doc.
- Midpoint gyro integration is not exact for time-varying 3D rate (coning ignored). The
  error-free truth test runs at several sample rates; the error must fall at the expected
  order as Δt shrinks.
- Ideal-attitude mode: `ins.py` receives an attitude sequence as input and does not know it
  comes from the truth.

## 2. Error budget (step 3): analytic references

Accel bias process, position error and variance (first-order GM started stationary,
C_Δ(u,v) = σ²(e^(−|u−v|/τ) − e^(−u/τ) − e^(−v/τ) + 1), components add):
```
δs(t) = ∫0^t (t−u) Δb_a(u) du,         Var = ∫∫ (t−u)(t−v) C_Δ(u,v) du dv
```
Pitch gyro (attitude error → gravity leakage → position):
```
δs_g(t) ≈ (g/2) ∫0^t (t−u)² Δb_g(u) du,   Var = (g²/4) ∫∫ (t−u)²(t−v)² C_Δ(u,v) du dv
```
(checked: constant b gives g·b·t³/6.)
- Vibration: E[δs] ≈ 0 to first order but Var(δs) > 0, and gyro-channel vibration need not
  average to zero through the rotation nonlinearity. Report mean, RMS, P95, sample-rate
  sensitivity, and the error-free-mechanisation consistency with vibration on. (Vibration is
  injected as sensor-level specific force/rate, not as truth motion.)
- Timestamp scale error, two analytic cases: constant speed δs ≈ ε·v₀·t (25 m/s, 180 s, 1 %:
  45 m, with zero forward specific force) and constant acceleration. Clock note (ours): errors
  are evaluated against the truth at the **true** sample time; GNSS is stamped by the same
  phone clock, so in a GNSS-aided filter a common clock-scale error partly cancels. v0.4 is
  INS-only, so the full effect shows.

## 3. Temperature stress (step 5, amends R5)

Accel and gyro ramps reported separately, ideal and free attitude side by side.
Analytic (zero bias/attitude error at entry, free mechanisation, 180 s):
- accel: b = ḃ·t, δs = ḃ·t³/6, ḃ = 5.3e-6 m/s³ → **5.15 m**
- pitch gyro: δθ = ḃ·t²/2, δs = g·ḃ·t⁴/24, ḃ = 4.7e-7 rad/s² → **202 m**

The gyro ramp, not the accel ramp, is the dominant temperature effect: small pitch-gyro errors
leak gravity into the forward axis. With the ramp running from the start of the drive, the
constant bias left after the calibration window and the later change are reported separately.

## 4. GNSS calibration windows (step 4)

Current scenarios give only 60 to 90 s of GNSS before the portal (1500 m approach): S1/S2
67.5 s, S3 77.2 s, S4 90 s, S5 60 s. 120 and 180 s windows are not possible.
Decision: lengthen the approach road. Ours: define it by time, **200 s of GNSS before the
portal for every scenario** [ASSUMED] (180 s window + margin). This changes the truth metrics
(durations, strapdown residuals); the change is recorded in the v0.4 CHANGELOG. A test must
also show that a longer GNSS history does not automatically improve bias observability.

Third calibration level split:
- **LS-ideal** (v0.4): true attitude and mount, bias from GNSS velocity only. Theoretical
  calibration limit; results stated as ideal.
- **LS-practical** (v0.5): estimated attitude/mount; estimates the lumped
  b_eff = b_a,∥ + g·δθ (sign by convention).

## 5. V1 to V6

| | Decision |
|---|---|
| V1 | Accepted. `ins.py` never imports truth; only the analysis harness reads truth. Oracle information as **independent** flags, not one `oracle=True`: `ideal_attitude`, `perfect_calibration`, `oracle_speed` (plus oracle initial state). |
| V2 | Three levels kept, LS split as in 4. "Perfect calibration" lists exactly what is known (IMU bias, scale factor, misalignment, mount angles, initial attitude, initial velocity). Two runs: all constants known (upper bound), bias only. Initial GNSS position/velocity errors are not mixed with IMU drift. |
| V3 | Accepted: along-track error at R. `p_R = p_P − C_nb r_b`; ideal experiments may use the true r_b and C_nb, normal algorithm tests use the estimator's assumed lever arm. Map projection `ŝ = argmin_s ‖p̂_R − p_map(s)‖²`, searched near the previous s (route continuity). |
| V4 | Accepted with two separate metrics: **localization error** (estimated vs true progress) and **exit-location / callout error** (map length error ε_L·L, e.g. 0.5 % of 3.5 km = 17.5 m ≈ 0.7 s at 25 m/s). The oracle is not charged the map error. |
| V5 | Conditionally accepted. Two analyses: **A. structural** (finite-window Gramian `W_o = Σ Φ_k,0ᵀ H_kᵀ R_k⁻¹ H_k Φ_k,0`, rank, weak directions, scaled before reading condition numbers; prior excluded) and **B. practical** (posterior covariance with initial covariance, process noise, realistic GNSS/NHC/baro R). Small covariance alone does not prove observability (priors shrink it). Bias states' frame stated explicitly (phone-frame biases enter through the mount matrix in the Jacobian); a state is added only if the measurement model is actually sensitive to it. |
| V6 | 200 seeds for development, 1000 for final comparisons; bootstrap CI for P95; paired comparisons (same seeds for all methods). Variance additivity checked, but expected only for the linear case: with free attitude, gyro and accel errors interact. |

## 6. Added experiments

- σ_s(t) growth curves, not only the exit value: shows from which time the gyro or the accel
  bias dominates (exponents 1.5 white, 2 constant accel bias, 3 constant pitch-gyro bias; GM
  biases need not follow these).
- Two reports: a **fixed 180 s budget** (fair comparison of error sources, INS runs 180 s
  from the portal regardless of tunnel length) and the **error at each scenario's real exit**
  (operational; S1 135 s, S3 180 s, S4 longer).

## 7. Order

1. Coordinate and measurement contracts (`docs/contracts.md`): C_bp/C_pb, state axes, bias
   frames, R/P references, sample timing, oracle boundaries.
2. Strapdown INS: ideal/free attitude, variable Δt, error-free tests at several rates.
3. Analytic + Monte Carlo budget: accel/gyro GM kernels, BI, vibration, timestamps.
4. Calibration and references: approach lengthened, windows, LS-ideal, CV, raw INS, oracle,
   separate map error.
5. Temperature stress: accel and gyro ramps, before/after calibration effects.
6. Observability: structural rank, weak modes, information matrix, posterior covariance.

Most valuable expected outcome: not which filter is good, but which error sources are
observable and correctable under which conditions, so the v0.5 state vector and measurement
models are designed with that knowledge.
