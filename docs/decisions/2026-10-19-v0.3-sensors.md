# v0.3 Sensor Simulation: Decisions (2026-10-19)

Status: **accepted**. Merged final version of the sensor proposal (K1 to K9) and the review
it received. From here on every decision and review enters the repository as a commit; the
repository is the only channel for synchronising work between sessions.

Section numbers below refer to `DESIGN.md`.

---

## 0. General decisions

**No real data is collected at this stage.** Sourced values are sufficient: phone Allan terms
from Suvorkin et al. 2024, bounds from the datasheet. Every parameter without a source stays
[ASSUMED] and is swept rather than pinned to a single value. Section 9 (real-device follow-up)
remains "later, optional".

**Tags go from two to three:**

| Tag | Meaning |
|---|---|
| [MEAS] | Value measured in a real experiment (e.g. Suvorkin Table 4) |
| [SPEC] | Datasheet / manufacturer specification (e.g. "LSM6DSR datasheet typ") |
| [ASSUMED] | Value chosen for the simulation, not validated |

The gap between Suvorkin and the LSM6DSR datasheet (accel VRW 1.7x, gyro ARW 8x the datasheet
noise density) is noted, but no cause is claimed (Android mode, bandwidth, filtering, Allan
extraction method are all possible). The value measured on the phone is used.

**Nominal and sensitivity are kept apart.** `profiles.py` holds one nominal configuration;
sensitivity scenarios are named overrides. No sensitivity value is ever a default.

**Version scope:**

| Version | Content |
|---|---|
| v0.3 | Sensor generators + sensor-level verification only (Allan/PSD, baro grade floor, timestamps, GNSS timing, reported accuracy) |
| v0.4 | Strapdown mechanisation; along-track error at the exit with each error term switched on alone, ideal attitude and perfect entry calibration (the measured version of the section 4 budget, recomputed); reference algorithms (last GNSS speed, raw integration, oracle); observability analysis |
| v0.5 | ESKF + NHC + ZUPT, NEES/NIS |
| v0.6 | IMM, map/baro grade layer |
| v0.7 | Monte Carlo, exit callout, exit recovery |
| v0.8 | Browser UI (Pyodide) |

In v0.3 scenario variants are **defined and tested**, but sweeps are run in v0.4. This split
keeps the v0.3 scope from growing.

## K1. Bias instability: three GM processes, single GM as reference

> **Revised (R2, R3 below):** target is the paper's parametric AVAR over 10 to 1000 s;
> τ = 5, 50, 500 s; verification by analytic fit + one 24 h run.

- Baseline model: sum of three first-order Gauss-Markov processes with τ = 30, 300, 3000 s
  [ASSUMED]. Weights σᵢ² = wᵢ·σ²_total are fitted to the OADEV curve. The 1.075·B scaling is
  **not** applied to each component separately.
- Reference model: single GM, τ = 300 s, σ = 1.075·B.
- Background: Suvorkin gives σ_A² = 2B²ln2/π for the flicker floor, i.e. floor ≈ 0.664·B. A
  first-order GM has its Allan peak 0.617·σ_ss at T = 1.89τ, so σ_ss = 0.664·B / 0.617 = 1.075·B.
- Verification: static simulation of at least 6 h, OADEV over 1 to 3000 s. Targets: floor region
  0.664·B ±10 %; −1/2 slope region VRW/ARW ±10 %. If a target is not met the parameters are not
  forced; the deviation is reported.
- Also reported: RMS bias change over 180 s, for both models. (Single GM, for reference:
  0.95·σ_ss at τ = 300 s; flicker floor: ≈ 0.94·B.)
- Documented as unknown: Suvorkin does not state at which averaging time B was read.

## K2. Android stream: uncalibrated

- Baseline: `TYPE_GYROSCOPE_UNCALIBRATED` (no software drift compensation; factory calibration
  and temperature compensation present).
- Gyro turn-on bias: nominal 0.05 °/s [ASSUMED]; sweep 0.2 and 1 °/s. The datasheet raw value
  ±1 dps [SPEC] is recorded as an upper bound, not used as nominal.
- Accelerometer turn-on bias: 10 mg [SPEC, LA_TyOff].
- Android's own bias estimate is not used (so the ESKF's own estimate is tested independently).
- Bias jump mid-drive in the calibrated stream: separate experiment, v0.5.

## K3. Temperature: exponential warm-up

> **Superseded (R4 below):** temperature drift is not modelled.

- T(t) = T₀ + ΔT∞ (1 − e^(−t/τ_th)), b_T = k_T (T − T₀); t counted from when the phone starts
  warming up.
- ΔT∞ = 15 °C, τ_th = 15 min [ASSUMED]. Tunnel entry at minute 5 and minute 20, two experiments.
- k_T: datasheet values [SPEC] (0.1 mg/°C accel, 0.005 dps/°C gyro) are upper bounds, because
  the Android stream may already be temperature compensated. **Nominal: 0.5 × SPEC [ASSUMED];
  sweep 0 and 1 × SPEC.**

## K4. Scale factor and misalignment

- The mount rotation (vehicle → phone, already in the truth) and the sensor axis misalignment
  (MEMS → phone axes) are kept as **separate** matrices.
- Gyro scale: nominal 0.3 % [ASSUMED], ±1 % [SPEC] as bound. Accelerometer scale: 3e-3 [ASSUMED].
- Separate heading error budget for curve matching: ε_ψ ≈ s_g · Δψ.

## K5. Vibration: 100 Hz baseline

> **Revised (R1 below):** vibration enters before the sensor scale/misalignment errors.

- Road component: broadband (≈ 2 to 30 Hz) scaled with speed. Engine component: narrow band
  (≈ 25 Hz at idle). Frequencies and amplitudes [ASSUMED]; two levels, "calm" and "noisy", are
  swept.
- No wheel tone is generated (section 5.2 decision).
- 1 kHz generation + low-pass + decimation: optional sensitivity test, not required in v0.3.
- Out of scope and stated explicitly: vibration rectification error (VRE). "Zero-mean vibration
  produces no bias" holds only for an ideal linear sensor.

## K6. Timestamps

- Timestamps carry the true measurement time. Three separate error scenarios:
  1. Sample-rate offset (±1 to 2 %), timestamps correct: the algorithm must not be affected.
  2. Timestamp scale error: accumulating error expected.
  3. Use of nominal dt (estimator-side error): tested in v0.4.
- The claim "1 % rate error → 45 m (25 m/s, 180 s)" applies only to cases 2 and 3 and is
  written in that corrected form.
- White jitter 0.5 ms [ASSUMED]; occasional sample gaps [ASSUMED].
- IMU–GNSS time offset: nominal 0, sweep 0 to 200 ms.

## K7. Barometer

- Model: h̃ = h + b_h0 + b_h,GM(t) + n_h + d_cabin(t) + d_tunnel(s).
- b_h0: constant within a drive [ASSUMED]. For its magnitude the manufacturer's definition of
  "relative accuracy" is checked; until verified it is used as a [SPEC] bound, and it is not
  called a "measured constant bias".
- White noise 0.1 m at 25 Hz [ASSUMED]; GM levels swept as in the table below.
- d_tunnel = k_p · s [ASSUMED], **swept in Pa/km** (1 Pa ≈ 8.5 cm of altitude, ρg ≈ 11.8 Pa/m).
- Verification: window length swept 5 to 60 s; Monte Carlo slope noise compared with the
  analytic formulas; the point where the T ≪ τ approximation breaks down is reported.
- Barometric grade depends on speed (sin γ ≈ ḣ / v). Three experiments for S1 (true speed,
  estimated speed, with cabin disturbance) are noted for v0.4/v0.5. Note: in a flat tunnel
  (γ ≈ 0) speed error barely affects grade; on a graded tunnel the grade error is ≈ γ · δv / v.
  A 5 % grade with 1 % speed error gives 0.05 % grade error, ≈ 4.9 mm/s², which is larger
  than the white-noise floor.
- A short literature search may be done on phone barometer noise and tunnel ventilation
  pressure gradients (no recording, literature only).

Grade floor from a least-squares slope over a 10 s window at 25 m/s (proposal-stage numbers,
Monte Carlo agrees with the formulas within 4 %):

| Noise [ASSUMED] | σ_ḣ [m/s] | Grade | Accel equivalent |
|---|---|---|---|
| white 0.1 m @ 25 Hz | 2.2e-3 | 0.009 % | 0.9 mm/s² |
| + GM(0.1 m, 60 s) | 6.4e-3 | 0.026 % | 2.5 mm/s² |
| + GM(0.3 m, 300 s) | 8.8e-3 | 0.035 % | 3.4 mm/s² |
| + GM(0.3 m, 60 s) | 1.8e-2 | 0.073 % | 7.1 mm/s² |

Formulas: white σ_ḣ = σ √(12 / (f T³)); correlated (T ≪ τ) σ_ḣ ≈ √(6q / (5T)), q = 2σ²/τ.
The worst row is ~20 % of the S5 mean drift (0.037 m/s²), so noise correlation changes the
CV/IMM detection floor.

## K8. GNSS velocity

- ṽ = v + b_v,GM + n_v. Two experiment families: total RMS fixed (white/correlated ratio
  varies) and total RMS increasing.
- To be defined explicitly: whether velocity is 3D, velocity direction accuracy, and
  position–velocity error correlation. Nominal: 3D, components independent [ASSUMED].
- Motivation: with white Doppler noise σ_v = 0.1 m/s at 1 Hz, a 60 s least-squares window gives
  an accel-bias calibration floor of 7.5e-4 m/s², the same level as bias instability
  (σ_b = σ_v √(12 / (f T³))).

## K9. Entry and exit

- Entry: two receiver behaviours. Nominal: measurements stop at signal loss. Scenario:
  "coasting", i.e. fake fixes propagated from the last receiver state (not from the truth), with
  growing reported accuracy.
- Exit: nominal is random-direction, time-correlated multipath (30 m, 8 s decay [ASSUMED]).
  "Lagging receiver" is a separate scenario; the two mechanisms are not mixed.
- Reported accuracy is generated independently of the true error. Three scenarios: calibrated
  (ratio 1), optimistic (0.7), pessimistic (1.5).

## Revisions (2026-10-19, IMU structure review)

**R1. Vibration order.** Vibration is a real specific force / angular rate, so it passes
through the sensor errors:
`f̃ = (I + S_a + M_a)(f_p + vib_a) + b_a,on + b_a,BI(t) + n_a` (same for the gyro).

**R2. Allan verification split in two.** A single 6 h run cannot show ±10 % at long T.
Measured run-to-run scatter of OADEV (1σ, sum of three GM, bias part only):

| Record | T = 100 s | T = 1000 s | T = 3000 s |
|---|---|---|---|
| 6 h | 4.9 % | 16.7 % | 24.4 % |
| 24 h | 2.2 % | 8.6 % | 10.9 % |
| 48 h | 1.4 % | 4.7 % | 7.6 % |

- (a) *Model vs paper:* analytic AVAR of the model (white + GM sum) vs target, ±10 % over the
  target range. Deterministic, no simulation.
- (b) *Code vs model:* one 24 h static run, fixed seed. ±10 % for T ≤ 300 s; for T > 300 s the
  tolerance is 3σ of the scatter above (~±30 % at 1000 s). Achieved values go to `metrics.json`.

*Correction at implementation (IMU commit):* the "±10 % for T ≤ 300 s" tolerance was not
backed by a scatter measurement at 300 s, and the table above was for the old τ set, bias part
only. Re-measured for the actual model (white + τ = 5, 50, 500 s; `tools/allan_scatter.py`,
150 runs of 24 h, worst axis, 1σ): 0.8 % at 10 s, 1.3 % at 30 s, 2.6 % at 100 s, 4.1 % at
300 s, 7.6 % at 1000 s. Tolerance is now `max(10 %, 3σ(T))` at every T, i.e. 10 % up to
100 s, 12.3 % at 300 s, 22.8 % at 1000 s. The seed (2026) was fixed before the run and is not
tuned. Result to note: gyro z at 300 s is +11.9 % (2.8σ), close to its tolerance; 40 further
seeds at 100 Hz give mean +0.5 %, 1σ 4.2 % for that point, so the generator is unbiased and
the value is one draw.

**R3. Navigation-oriented Allan target.** A single flat "floor region" cannot be defined for
all axes: the white/floor crossover is T_c = (N / 0.664B)² = 0.6 s (accel z) to 142 s
(gyro x), so on gyro x white noise dominates most of 100 to 3000 s. The paper gives one
number per axis and does not say at which T it was read. Decision:
- Target is the paper's own parametric model (Suvorkin Table 2):
  `AVAR_target(T) = N²/T + (2 ln2 / π)·B²`, N and B [MEAS].
- Target range 10 to 1000 s [ASSUMED]: from short tunnels up to the longest case
  (S4: calibration window + 337 s outage ≈ 460 s) with margin. Beyond 1000 s the curve is
  reported, not targeted.
- GM correlation times are derived from the range, not chosen independently (a GM's Allan
  peak is at T = 1.89τ, so τ_min ≈ T_lo/2, τ_max ≈ T_hi/2): **τ = 5, 50, 500 s** [ASSUMED].
  Weights by NNLS on the analytic AVAR. Fit check, worst axis over 10 to 1000 s:

| τ set | worst-axis ADEV error |
|---|---|
| 30, 300, 3000 s (original K1) | accel z 27 %, accel x 19 % |
| 10, 100, 1000 s | accel z 8 % |
| 5, 50, 500 s | ≤ 2 % on all axes |

- Reference model (single GM, τ = 300 s, σ = 1.075·B) is reported against the same target.
- Per-axis values over the outage horizon (30 to 300 s) are reported.

**R4. Temperature drift not modelled.** The IMU is assumed calibrated including temperature;
the residual (turn-on) bias is estimated by the filter while GNSS is available; temperature
change inside the tunnel is neglected, in the filter and in the truth. Reason: it is not
observable inside the tunnel, so a filter state would add nothing, and modelling it pulls the
work towards IMU calibration, away from the navigation question. Recorded as a known
limitation with its size: with the earlier assumptions (0.5 × SPEC, ΔT∞ 15 °C, τ_th 15 min,
entry at minute 5) the tunnel would see ~1.95 °C over 3 min, i.e. ~9.6e-4 m/s² accel bias and
~8.5e-5 rad/s gyro bias change, the same order as bias instability. In-tunnel bias change
remains in the truth through the bias-instability GM processes.

## Infrastructure

- New module `tunnelsim/sensors.py`. Its output contains only measured fields (section 7.2);
  error components live in a separate object that is never passed to the estimator.
- Every error term can be switched on and off separately. **Each component has its own RNG
  stream** (`np.random.SeedSequence.spawn`): switching one term off does not change the samples
  of any other term.
- `metrics.json` gets a `sensors` section: every metric carries target, achieved and tolerance.

## v0.3 tests

1. Static IMU OADEV vs Suvorkin Table 4 (K1 targets).
2. RMS bias change over 180 s, reported for both models.
3. Baro grade floor vs analytic formulas, window sweep.
4. Timestamps: no effect in scenario 1; expected accumulation in scenario 2.
5. GNSS: no fix inside the tunnel (nominal); in the coasting scenario fixes come from the last
   receiver state; re-acquisition timing; reported-accuracy ratios.
6. RNG independence: switching one term off does not change the samples of other terms.

## Four principles to keep

1. Sensor truth, error components and estimator inputs are strictly separate.
2. Every physical effect is defined by either a sourced or an explicitly assumed parameter.
3. Nominal and stress scenarios are not mixed.
4. Scenarios with weak observability, such as S1 and S5, are reported in every version.

Evaluation criterion: not that an algorithm gives a better result, but that we can explain,
mathematically and experimentally, **which information** it uses to give that better result.
